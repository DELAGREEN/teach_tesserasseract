# Teach Tesseract

Проект предназначен для обработки PDF-документов с использованием OCR, извлечения текста и подготовки структурированного текстового слоя для последующего анализа, проверки и исправления. Основная задача — повысить качество распознавания кириллического текста в документах, где стандартный текстовый слой либо отсутствует, либо неудовлетворительный.

## Что умеет проект

- извлекать текст из PDF через PyMuPDF и связанные PDF-методы;
- обнаруживать наличие исходного текстового слоя в документе;
- запускать OCR, если текстовый слой отсутствует или является низкого качества;
- нормализовать и очищать текст после распознавания;
- удалять или корректировать артефакты, лишние символы и ошибки распознавания;
- работать с кириллицей и типографскими шрифтами, характерными для технической документации;
- обрабатывать документы через веб-админку и поддерживать локальный запуск через Python-скрипты.

## Основные компоненты

- `main.py` — точка входа для запуска основных сценариев приложения;
- `admin_app.py` — веб-интерфейс администратора и API для загрузки и обработки PDF-файлов;
- `pdf_processors.py` — ядро обработки PDF: чтение страниц, анализ текста, подготовка OCR-пайплайна;
- `ocr_processor.py` — логика распознавания текста через Tesseract и дальнейшая постобработка;
- `api_client.py` — клиент для интеграции с внешними сервисами и HTTP-эндпоинтами;
- `logger.py` — логирование операций и диагностики;
- `tests/` — регрессионные и функциональные тесты;
- `docker/` — Docker-окружение и запуск проекта в контейнере;
- `fonts/` — шрифты, используемые в составе проекта;
- `trained_data/` — языковые данные Tesseract, включая `rus.traineddata`;
- `test_server/` — служебный сервер и конфиги для локальной проверки;
- `pdf/` — примеры PDF-файлов для тестов и отладки.

## Архитектура и поток данных

Процесс обработки в проекте строится как последовательный пайплайн:

1. Загрузка PDF-файла через админ-панель или вызов Python-кода.
2. Анализ документа на уровне страниц: проверяются метаданные, формат PDF, наличие текста в слое документа.
3. Если текстовый слой есть и его качество приемлемо, дальнейший OCR может не запускаться.
4. Если исходный текст отсутствует, повреждён или низкого качества, запускается распознавание через Tesseract.
5. На выходе OCR-текст проходит нормализацию: удаление мусорных символов, выравнивание текста, объединение частей слов и фильтрация дефектов.
6. Результат сохраняется в логах, в структуре проекта или используется интерфейсом администратора.

Этот подход делает систему гибкой: она может работать как на чистом PDF-парсинге, так и на OCR-распознавании в зависимости от исходного файла.

## Подробный раздел: как устроен OCR-пайплайн

Ниже — основная логика работы проекта от момента загрузки документа до финального текста.

### 1. Подготовка входного файла

На вход подаётся PDF-документ. На этом этапе система проверяет:

- формат файла;
- корректность чтения страницы;
- наличие в PDF исходного текстового слоя;
- наличие изображений, которые будут распознаваться через OCR;
- метаданные и тип содержимого страницы.

Если PDF уже содержит текст, проект может использовать его как базовый источник. Если текст отсутствует или выглядит повреждённым, система переходит к OCR.

### 2. Проверка текстового слоя

Основной вопрос на этом этапе: "Есть ли уже текст в документе?". В проекте это проверяется на основании анализа PDF-страниц и содержимого, которое извлекается из документа.

Важные проверки:

- есть ли извлечённый текст для страницы;
- соответствует ли текст ожиданиям по длине и структуре;
- нет ли большого количества мусорных символов;
- присутствуют ли русские слова и корректные разделители.

Если проверка покажет, что текст слишком плохой, приложение считает документ "OCR-необходимым".

### 3. Извлечение текста из PDF

Если исходный текст существует, он извлекается и сохраняется как промежуточный результат. Это позволяет:

- не распознавать заново уже валидный документ;
- сравнивать OCR-результат с исходным текстом;
- находить места, где качество ниже ожидаемого;
- снижать вероятность повторных ошибок.

На этом этапе можно также анализировать долю страниц, где текст читается нормально, и страницы, которые требуют распознавания.

### 4. Запуск Tesseract OCR

Если документ не удовлетворяет критериям качества, запускается OCR. Для этого проект использует Tesseract с языковыми данными, включая русский язык.

На этом этапе:

- документ обрабатывается постранично;
- страницы могут быть преобразованы, улучшены или подогнаны под OCR;
- распознавание идёт по изображениям и текстовым элементам страницы;
- результат сохраняется как промежуточный OCR-текст.

### 5. Постобработка распознанного текста

Этот этап критически важен. Сам OCR часто даёт шум: лишние символы, неправильные буквы, слитные слова, перевёрнутые символы и фрагменты текста.

В проекте есть кастомная логика, которая:

- очищает мусор; 
- объединяет строки и слова в читаемый текст;
- убирает повторяющиеся артефакты;
- нормализует символы, типичные для OCR-помех;
- пытается восстановить корректную русскую раскладку текста;
- фильтрует результаты, которые выглядят явно ложными.

Именно этот этап делает проект не просто "OCR-обёрткой", а системой, ориентированной на качество текста для технической и документной обработки.

### 6. Сравнение результатов и оценка качества

После OCR система сравнивает итоговый текст с исходным извлечением, если таковое было доступно. Это позволяет оценить:

- качество распознавания;
- наличие числовых, графических или структурных потерь;
- стабильность обработки на разных страницах;
- необходимость дополнительной настройки OCR.

В долгосрочной перспективе эта же логика может использоваться для интеллектуальной маршрутизации документов: от простых случаев к более сложным.

### 7. Вывод данных в интерфейс или в файл

Окончательный результат может быть:

- показан в веб-админ панели;
- сохранён в логах;
- передан в другой модуль или API;
- использован повторно в процессе проверки.

Таким образом проект поддерживает как локальный сценарий, так и серверный, управляемый через админку.

## Схема пайплайна

```text
PDF-файл
   ↓
Проверка PDF-слоя / структуры страницы
   ↓
Есть ли текст? → Да / Нет
   ↓
Да → извлечение исходного текста
Нет → запуск Tesseract OCR
   ↓
OCR-текст
   ↓
Постобработка и нормализация
   ↓
Сравнение с исходным текстом / оценка качества
   ↓
Результат для интерфейса, логов или дальнейшей обработки
```

## Требования

Минимальные требования:

- Python 3.11+
- Tesseract OCR
- pip / virtualenv
- библиотеки из `requirements.txt`

Для Linux может потребоваться:

- `tesseract-ocr`
- `tesseract-ocr-rus`
- системные зависимости для PDF и шрифтов

## Быстрый старт

### 1. Клонирование

```bash
git clone <repository-url>
cd teach_tesserasseract
```

### 2. Создание виртуального окружения

```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Подготовка окружения

Создайте файл `.env` по примеру:

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change_me
```

Если проект использует дополнительные переменные окружения, их значения можно проверить в `.env`, `config.ini` и служебных конфигурациях.

### 4. Запуск веб-админ панели

```bash
python admin_app.py
```

или в ASGI-режиме:

```bash
uvicorn admin_app:app --host 0.0.0.0 --port 5002 --reload
```

### 5. Запуск основных сценариев проекта

```bash
python main.py
```

## Использование админ панели

Админ панель предназначена для:

- входа в защищённую область;

- отслеживания статуса обработки;
- просмотра логов и промежуточных результатов.

Обычно интерфейс доступен по адресу:

```text
http://localhost:5002
```

## Полезные заметки

- Для кириллицы критически важны корректные данные Tesseract и правильная установка языковых моделей.
- Если OCR даёт шум, прежде всего стоит проверить исходный PDF-текстовый слой и качество шрифтов.
- Логи, формируемые через `logger.py`, полезны для диагностики ошибок на этапах извлечения, распознавания и очистки текста.
- При разработке новых сценариев лучше сначала проверять отдельные страницы и отдельные типы документов, а потом расширять пайплайн.

## Рекомендуемый рабочий процесс

1. Подготовить PDF-файл и проверить, есть ли в нем исходный текстовый слой.
2. Запустить обработку через админ-панель или Python-скрипты проекта.
3. Проконтролировать качество извлечённого текста и OCR-результата.
4. При необходимости настроить параметры обработки и повторно выполнить распознавание.
5. Зафиксировать успешные сценарии и использовать их как основу для дальнейших улучшений.
